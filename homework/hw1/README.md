# Московский зоопарк — консольное приложение (Kotlin + Koin)

- Консольное приложение: есть цикл обработки команд (`tui/CommandDispatcher.kt`).
- Приём новых животных/вещей: команда `create`.
  `tui/builders/**`).
- Проверка здоровья перед приёмкой: для животных вызывается `VetClinic.checkup` в `CreateCommand`. В проекте есть пример
  клиники `ExampleVetClinic` с логикой принятия/отклонения.
- Отчёт по животным и их рациону: `list_animals`
- Список животных для контактного зоопарка: `list_contact_zoo`
- Инвентаризация: все сущности на балансе реализуют `Inventory` (через базовый `Thing`), у всех есть `inventoryId` и
  `inventoryName`. Команда `list_things` выводит наименование и инвентарные номера.
- DI‑контейнер: используется Koin. Привязки задаются в `Main.kt`, внедрение через `KoinComponent` в командах и
  валидаторе.
- Юнит‑тесты: покрытие 62% строк. Тесты запускаются `./gradlew test`.

## Архитектура и доменная модель

- Базовые интерфейсы:
    - `interfaces.Inventory` — у всего, что стоит на балансе, есть `inventoryId` и `inventoryName`.
    - `interfaces.Alive` — у живых есть `eatsKg` (кг в день).
    - `interfaces.VetClinic` — стратегия проверки здоровья с результатом `Accept/Reject`.
- Базовые классы:
    - `domain.Thing` (абстрактный) — общая база для инвентаризируемых сущностей (включая животных).
    - `domain.animals.Animal` (абстрактный) — животные, реализуют `Alive`.
    - `domain.animals.Herbo` — травоядные с полем `kindness` и методом `isKind()`
    - `domain.animals.Predator` — хищники с `preyList`.
- Конкретные сущности животных: `Rabbit`, `Monkey`, `Tiger`, `Wolf`. Вещи: `Table`, `Computer`.
- Репозиторий: `interfaces.ThingRepository` и реализация `SimpleThingRepository` (память, защита от дубликатов
  `inventoryId`).
- Ветклиника: `ExampleVetClinic` — пример логики осмотра.
- Консольный интерфейс:
    - Диспетчер команд `tui/CommandDispatcher.kt`.
    - Команды в `tui/commands/**`.
    - Диалоговые «билдеры» параметров в `tui/builders/**`
- Валидации: `validators/**` — независимые проверки полей, используемые в диалогах билдеров.
- Печать: `printers/**` — человекочитаемое представление сущностей для вывода и подтверждения.
- Модель параметров: у каждого класса есть вложенный интерфейс `Params` (например, `Animal.Params`), позволяющий
  собирать параметры пошагово и делегировать их вниз по иерархии (избегаем «телескопических» конструкторов).

### DI и модульность

- DI-контейнер: Koin (`io.insert-koin:koin-core`).
- Привязки задаются в `Main.kt`:
    - `ThingRepository` → `SimpleThingRepository` (singleton).
    - `VetClinic` → `ExampleVetClinic` (singleton).
- Потребители объявляют зависимость через `KoinComponent` и получают её с помощью `get()` (например, `CreateCommand`,
  `List*Command`, `ThingValidator`). За счёт этого легко заменить реализации для тестов или расширений.

## ООП и SOLID

- Инкапсуляция: поля сущностей доступны через свойства только для чтения; создание проходит через `Params` и
  валидаторы/билдеры.
- Наследование: иерархия `Thing → Animal → (Herbo | Predator) → конкретные виды`.
- Полиморфизм: обработка по базовому типу (`Thing`, `Animal`) с распределением в принтерах и командах по конкретным
  подтипам.

Принципы SOLID:

- Single Responsibility (SRP):
    - Репозиторий хранит/проверяет уникальность; клиника занимается только проверкой здоровья; валидаторы валидируют
      поля; принтеры отвечают за вывод; билдеры — за диалог ввода; команды — за сценарии.
- Open/Closed (OCP):
    - Добавление новых видов животных/вещей не требует изменения базовых классов; добавляем новый
      класс+валидатор+принтер+билдер и подключаем его к регистрациям (мапам) соответствующего уровня.
- Liskov Substitution (LSP):
    - Любой `Herbo`/`Predator` — это `Animal`, любой `Animal` — это `Thing`. Код, работающий с базовым типом (например,
      репозиторий, листинги), не зависит от конкретного подтипа.
- Interface Segregation (ISP):
    - Небольшие специализированные интерфейсы `Inventory`, `Alive`, `VetClinic` вместо «толстых» контрактов.
- Dependency Inversion (DIP):
    - Команды и валидаторы зависят от абстракций (`ThingRepository`, `VetClinic`), а реализация выбирается
      DI-контейнером Koin.
