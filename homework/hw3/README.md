# Антиплагиат

Система антиплагиата в микросервисной архитектуре.

## Развертывание
- `docker compose up`
- После запуска публичный интерфейс доступен на `http://localhost/`.
- Для демонстрации внутренние сервисы проброшены на хост: work_main_api `http://localhost:18080`, file_storage `http://localhost:18081`, work_analyzer `http://localhost:18082`.

## Архитектура
- **work_main_api** - внешний API: загрузка работы, получение отчета, построение облака слов; координирует обращения к другим сервисам.
- **file_storage** - сохраняет файлы по SHA-256 и умеет отдавать по хэшу или id работы.
- **work_analyzer** - асинхронно рассчитывает отчеты: ищет дубликаты по хэшу среди других авторов.
- **router (nginx)** - единая точка входа, проксирует внешние запросы.
- **db (PostgreSQL)** - хранит метаданные работ и результаты анализа.
- Все сервисы упакованы в Docker; `docker compose up` разворачивает всю систему и прогоняет `db_init.sql` через `db_init`.

## Пользовательские сценарии и потоки данных
- **Загрузка работы** `POST /works`: валидация ввода, загрузка файла в file_storage, запись метаданных в БД, единичный вызов work_analyzer для старта анализа
- **Получение отчета** `GET /works/{id}/report`: при отсутствии результата снова единично вызывает work_analyzer, возвращает `202 Accepted` со статусом `running`/`pending` пока отчет не готов; при готовности - статус `completed`, флаг `is_plagiarism` и список совпавших работ (по id); при ошибке анализа - статус `failed` с `error`
- **Перезапуск анализа** `POST /works/{id}/reanalyze`: очищает прошлые результаты и повторно запускает анализ (возвращает `202 Accepted`)
- **Скачивание работы** `GET /works/{id}/download`: router проксирует в file_storage, который читает файл по сохраненному хэшу
- **Облако слов** `GET /works/{id}/wordcloud`: work_main_api забирает файл из file_storage, проверяет, что это UTF-8 текст до 512KB и он не пустой, и отправляет текст во внешний сервис wordcloud (`quickchart.io`) для получения PNG
- **Внутренние маршруты**: file_storage `POST /upload`, `GET /download/{hash}` (оба с `Authorization: Bearer <ACCESS_PASSWORD>`), work_analyzer `POST /analyze`, вызываются только из work_main_api.

## Алгоритм определения признаков плагиата
1. При загрузке file_storage считает SHA-256 файла и сохраняет его на диск под этим хэшем; метаданные (автор, задание, комментарий, хэш) сохраняются в таблицу `works`
2. work_main_api запускает work_analyzer асинхронно (чтобы пользователь сразу получил id созданной работы).
3. work_analyzer читает метаданные работы и ищет в `works` все записи с тем же `file_sha256`, другим `author_name` и другим id.
4. Если совпадений нет - сохраняет результат проверки без поля `stolen_from_id`; если есть - создает запись результата для каждой найденной работы с указанным `stolen_from_id`.
5. Запрос отчета возвращает все найденные совпадения по id; отсутствие записей означает, что отчет еще не построен.

## API маршруты (через роутер)
- `POST /works` - загрузить работу (file, author_name, assignment_name, comment)
- `GET /works/{id}/report` - готовность и содержимое отчета (при отсутствии результата дополнительно триггерит анализ один раз; может вернуть `running`/`pending` пока анализ выполняется)
- `POST /works/{id}/reanalyze` - очистить результаты и запустить анализ заново
- `GET /works/{id}/wordcloud` - PNG облако слов по тексту работы
- `GET /works/{id}/download` - скачать исходный файл работы

Внутренние маршруты (используются сервисами напрямую):
- file_storage: `POST /upload` и `GET /download/{hash}` с заголовком `Authorization: Bearer <ACCESS_PASSWORD>`
- work_analyzer: `POST /analyze` - запускает анализ по work_id

## Документация
- Postman коллекция: `docs/api.postman_collection.json`
- Переменные окружения в `.env` (пароль БД, пароль file_storage, уровни логирования)
- Интеграционный тест публичного API: `cargo run -p integration_test` (см. [integration_test/src/main.rs](integration_test/src/main.rs)); генерирует помеченные тестовые работы и проверяет загрузку, отчет, переанализ и скачивание
